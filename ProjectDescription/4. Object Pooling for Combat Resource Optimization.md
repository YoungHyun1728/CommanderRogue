### 4. 오브젝트 풀링을 이용한 최적화

이 문서에서는 CommanderRogue 전투 시스템에서 오브젝트 풀링이 실제로 적용된 부분과, 그 목적이 무엇인지 설명합니다.

전투 게임에서는 짧은 시간 안에 같은 종류의 오브젝트가 반복해서 생성되고 사라집니다.  
특히 투사체, 히트 이펙트, 데미지 텍스트는 한 번의 전투에서 수십 번에서 수백 번까지 발생할 수 있기 때문에, 매번 `Instantiate`와 `Destroy`를 반복하면 메모리 할당과 해제가 잦아지고 GC 부담이 커질 수 있습니다.

그래서 이 프로젝트에서는 `반복 생성 빈도가 높고 수명이 짧은 전투 리소스`를 중심으로 오브젝트 풀링을 적용했습니다.

### 적용 대상

현재 실제로 풀링이 적용된 전투 리소스는 다음 3가지입니다.

- `Projectile`
  기본 공격 투사체와 스킬 투사체를 재사용합니다.
- `VFX`
  피격, 버프, 디버프, 폭발 등의 전투 이펙트를 재사용합니다.
- `Floating Text`
  데미지, 회복, 상태이상, 시스템 메시지 텍스트를 재사용합니다.

이 세 종류는 모두 `짧게 생성되었다가 바로 사라지고`, 전투 도중 같은 프리팹이 매우 자주 반복 호출된다는 공통점이 있습니다.  
따라서 전투 중 체감 성능에 직접 영향을 주는 우선순위 높은 최적화 대상이라고 볼 수 있습니다.

### 1. Projectile 풀링

투사체 풀링은 `ProjectilePoolManager`와 `Projectile`를 중심으로 구성되어 있습니다.

- `ProjectilePoolManager`
  투사체 타입별로 `ProjectilePoolEntry`를 두고, 각 엔트리에 `Queue<Projectile>`를 유지합니다.
- `ProjectilePoolEntry`
  `ProjectileType`, 프리팹, 초기 생성 개수를 들고 있어 Inspector에서 타입별 풀 크기를 조절할 수 있습니다.
- `Projectile`
  자신이 어떤 풀 엔트리에서 나왔는지 기억하고 있다가 수명이 끝나면 다시 풀로 반환됩니다.

동작 방식은 다음과 같습니다.

1. 게임 시작 시 `ProjectilePoolManager`가 각 타입별 `initialSize`만큼 투사체를 미리 생성해 비활성화 상태로 큐에 넣습니다.
2. 기본 공격이나 스킬이 투사체를 발사할 때 `ProjectilePoolManager.Get()`으로 오브젝트를 꺼냅니다.
3. 꺼낸 투사체는 위치와 회전을 초기화한 뒤 활성화되고, 공격 대상이나 스킬 정보를 다시 세팅합니다.
4. 충돌하거나 수명이 끝나면 `Projectile.Despawn()`이 호출되고, 이 오브젝트는 `Destroy`되지 않고 다시 큐로 반환됩니다.

즉, 전투 중 계속 날아다니는 화살, 표창, 마법탄은 매번 새로 생성되는 것이 아니라 `한 번 만들어 둔 오브젝트를 재활용`하는 구조입니다.

#### 작동 흐름

- 기본 공격 발사 시 `UnitFSM`이 `ProjectilePoolManager.Instance.Get()`으로 투사체를 가져옵니다.
- 스킬 발사 시 `SE_SpawnProjectileToTarget`, `SE_SpawnProjectileForward`가 같은 풀 매니저를 사용합니다.
- 피격 후 관통 수가 다했거나 수명이 끝나면 `Projectile`이 스스로 풀로 복귀합니다.

이 구조 덕분에 가장 자주 생성되는 전투 오브젝트 중 하나인 투사체의 생성/삭제 비용을 크게 줄일 수 있습니다.

### 2. VFX 풀링

시각 효과는 `VfxPoolManager`와 `VfxObject`를 통해 풀링됩니다.

- `VfxPoolManager`
  `VfxType`별로 풀 엔트리를 관리하고, 엔트리마다 `Queue<VfxObject>`를 유지합니다.
- `VfxObject`
  재생 시간 동안만 활성화되었다가, 지정 시간이 지나면 자동으로 풀에 복귀하는 전용 VFX 래퍼입니다.

동작 방식은 다음과 같습니다.

1. `VfxPoolManager`가 시작 시 타입별 `initialSize`만큼 VFX를 미리 생성합니다.
2. 스킬이나 피격 처리에서 `VfxPoolManager.Get()`을 호출하면 적절한 타입의 VFX를 꺼내 활성화합니다.
3. `VfxObject.Play(duration)`이 재생 시간을 기준으로 코루틴을 돌립니다.
4. 시간이 끝나면 `Despawn()`으로 다시 풀에 반환합니다.

특히 이 구조는 `Projectile`과 자연스럽게 연결됩니다.  
투사체가 적에게 맞았을 때 `Projectile` 내부에서 히트 VFX를 호출하고, 이때도 새 이펙트를 생성하지 않고 VFX 풀에서 가져와 사용합니다.

또한 스킬 이펙트 계층에서도 `SE_SpawnVfxOnCasterTile`, `SE_SpawnVfxOnTargetTile`, `SE_SpawnVfxFollowUnit` 같은 효과들이 동일한 풀 매니저를 사용합니다.  
즉, 이 프로젝트의 전투 이펙트는 대부분 `VfxType` 기반 공용 풀을 통해 관리됩니다.

### 3. Floating Text 풀링

데미지 숫자와 상태이상 텍스트는 `FloatingTextPoolManager`와 `FloatingTextItem`으로 관리됩니다.

- `FloatingTextPoolManager`
  미리 `prewarm` 개수만큼 텍스트 오브젝트를 생성해 두고, 필요할 때 큐에서 꺼내 씁니다.
- `FloatingTextItem`
  텍스트 내용, 색상, 폰트 크기, 상승 애니메이션, 페이드아웃을 재생한 뒤 완료되면 다시 풀에 반환됩니다.

동작 방식은 다음과 같습니다.

1. 시작 시 텍스트 프리팹을 미리 생성해 비활성화 상태로 보관합니다.
2. 데미지, 힐, 상태이상, 시스템 메시지가 발생하면 `ShowDamage`, `ShowHeal`, `ShowStatus`, `ShowSystem` 같은 API를 통해 텍스트를 꺼내 표시합니다.
3. 텍스트는 UI 좌표로 변환된 뒤 상승, 스케일, 페이드 애니메이션을 재생합니다.
4. 애니메이션이 끝나면 `OnDone` 콜백을 통해 다시 풀로 돌아갑니다.

추가로 같은 대상에게 짧은 시간 안에 여러 텍스트가 연달아 뜰 경우, 기존 텍스트를 위로 밀어 올리는 스태킹 처리도 포함되어 있습니다.  
즉, 이 시스템은 단순 풀링뿐 아니라 `전투 로그를 읽기 쉬운 형태로 정리하는 UI 역할`도 함께 담당합니다.

실제 사용 범위도 넓습니다.

- `Unit`에서 데미지, 회복, 시스템 문구 출력
- `UnitStatusEffectController`에서 상태이상 출력
- `UnitFSM`과 일부 스킬 효과에서 보조 메시지 출력

전투 중 가장 자주 눈에 보이는 UI 요소 중 하나이기 때문에, 이 부분에 풀링을 적용한 것도 체감 최적화 측면에서 의미가 큽니다.

### 4. 왜 이 3개에 적용했는가

현재 풀링 대상은 모두 다음 조건을 만족합니다.

- 생성 빈도가 매우 높다.
- 화면에 머무는 시간이 짧다.
- 종류는 정해져 있지만 호출 횟수는 많다.
- 같은 오브젝트를 재사용해도 게임 로직상 문제가 없다.

이러한 조건을 가장 강하게 만족하는 것이 바로 `투사체`, `전투 VFX`, `전투 텍스트`입니다.  
그래서 프로젝트 초점도 `전투 프레임에 직접 영향을 주는 단기 오브젝트 최적화`에 맞춰져 있습니다.

### 5. 정리

CommanderRogue의 오브젝트 풀링은 전투 중 반복 생성이 가장 많은 리소스를 우선 대상으로 삼아 적용되었습니다.

- `ProjectilePoolManager`는 기본 공격/스킬 투사체를 재사용합니다.
- `VfxPoolManager`는 피격 및 스킬 이펙트를 재사용합니다.
- `FloatingTextPoolManager`는 데미지와 상태 텍스트 UI를 재사용합니다.

이 구조를 통해 전투 중 불필요한 `Instantiate/Destroy` 호출을 줄이고, 메모리 할당과 GC 부하를 완화해 보다 안정적인 전투 흐름을 만드는 것이 목적입니다.

따라서 이 문서에서는 “오브젝트 풀링이 적용된 모든 지점”을 나열하는 것 자체도 중요하지만, 더 핵심적인 포인트는 `어떤 리소스를 왜 풀링 대상으로 선택했는가`를 함께 설명하는 것입니다.
